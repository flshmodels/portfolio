Roblox CAD
Bridge

A 911 call in the game needs a way to reach the dispatch system outside it.

This bridge carries 911 calls, unit updates and panic alerts from a Roblox server to a computer-aided dispatch backend. The game server checks the event first, then sends it to an HTTP receiver. A separate adapter translates the result into the fields your CAD uses.

The interesting part is what happens when delivery goes wrong. There’s a temporary queue, request budgeting and retries with backoff. The receiver keeps sessions and servers separate, and the CAD reader uses its own read-only credentials.

Inside the project

The Luau services own player identity, location and duty checks. The Node receiver validates incoming records and stores a snapshot. An example mapper shows how to turn that snapshot into calls, units and panic records for another application.

This is a starting point for an integration. You still need to host an HTTPS receiver and write the final CAD adapter. The queue is held in memory, so it can lose pending events on shutdown. Receiver acceptance also doesn’t mean a dispatcher has seen the call. Live Roblox behavior still needs verification.

Flash Canvas

Try a small interface in the browser. Take the layout back to Studio.

Canvas reads a JSON layout and previews frames, labels and buttons at different sizes. Once the layout is valid, it exports a Luau function that creates the GUI. The preview runs locally in the browser, without an account or a server.

It focuses on the awkward bit of Roblox UI: how scale, offset and anchors work together. The export keeps those values instead of fixing everything to one screen size. You get the interface structure, then connect the buttons to your own game code.

Inside the project

Parsing, validation, geometry and Luau generation share one layout module. The browser builds its preview with DOM elements. After an edit, export stays disabled until the next valid render, so the downloaded code matches the checked layout.

The preview is deliberately small: Frame, TextLabel and TextButton. It doesn’t use Roblox’s renderer, and fonts, wrapping and clipping can differ. Check the exported GUI in Studio before using it in a game.

Flash Inspect

Find the small mistakes that are easy to miss in a large place.

A scenery part can be left unanchored. Two doors can end up with the same interaction ID. Inspect scans tagged objects for those problems and lists the findings in a Studio panel. Click a result to select the object and check it yourself.

The checks stay narrow: unanchored static scenery, invalid interaction IDs, and duplicate IDs. It leaves the place alone. A welded part might be unanchored on purpose, so a finding is something to review, rather than an automatic fix.

Inside the project

You can scan Workspace or the current selection. Overlapping selections are deduplicated, and a scenery tag on a parent still applies to its descendants. Every object affected by a duplicate ID is included in the results.

Duplicate checks only cover the scanned scope. Results are snapshots, so rescan after making changes. The plugin refuses play-mode scans and stops above its object limit. Its dock panel and installation still need testing in a live Studio session.
